🏫

학생 서비스

학교 선택부터 신고 접수, 처리 확인과 참여까지 학생이 쓰는 기능

1. 프로젝트 개요

“복도 타일이 들떠서 넘어질 뻔했다” 같은 제보가 종이나 구두로 흩어지지 않고, 접수번호와 위험도가 남는 기록으로 관리되게 하는 웹 서비스입니다. 학생은 로그인 없이 신고하고, 교사·운영진은 개인 계정으로 처리 상태와 답변을 관리합니다.

🔓 로그인 없음

회원가입·로그인 없이 학교만 고르면 바로 신고합니다. 내 신고는 브라우저의 익명 소유 토큰으로 구분합니다.

🙈 개인정보 미수집

이름·학번·연락처를 받지 않습니다. API 응답도 화이트리스트 DTO로만 내보내 IP·내부 식별자가 나가지 않습니다.

📢 처리 과정 공개

누구나 학교별 신고 목록, 처리 상태, 위치별 현황을 볼 수 있습니다. 공개 보류 신고만 운영진 검토 뒤 공개됩니다.

사용자접속 방식주요 일
학생로그인 없음신고 작성·조회, 공감·만족도·추가 설명, 처리 알림
교사개인 계정 또는 학교 공용 비밀번호소속 학교 신고의 상태·담당자·처리 메모·학생 답변
운영진개인 계정모든 학교 신고 처리·삭제, 공개 보류 검토, 학교 신청·등록, 알림 설정
관리자 · 총괄개인 계정계정 관리, 삭제된 신고 복구, 운영 기록, 백업·되돌리기

2. 신고 접수 흐름

  1. 학교 선택첫 접속에서 지원 학교(54곳)를 고르면 그 학교의 위치 유형과 세부 장소 카탈로그가 적용됩니다.
  2. 신고 작성“빠르게 시작하기” 카드와 단계 ①–④로 제목·장소·문제 종류·설명을 채웁니다. 예시, 사진 한 장으로 신고, 소음 재기를 쓸 수 있습니다.
  3. 서버 검사허용된 위치·종류와 길이를 확인하고, 욕설 필터와 글·사진 안전성 검사(Moderation)를 거칩니다.
  4. AI 사전 확인담당자가 어디서 무엇을 확인할지 알 수 있는지 판단합니다.
    부족하면 질문 1개를 되묻고(HTTP 422, 저장 안 함), 답을 합쳐 다시 판단합니다. 최대 3회.
  5. 위험도 분석AI가 5개 요소를 0~4점으로 채점하고, 점수와 등급은 서버가 공식으로 계산합니다.
  6. 저장 · 안내접수번호(REP-YYYYMMDD-NNNN)와 다른 기기용 확인 코드를 한 번 보여 줍니다. 반복 신고 기기·안전성 검사 대상은 공개 전에 운영진 검토로 보류됩니다.

3. 신고 작성 화면

화면 구성

  • 한 열 가운데 정렬, 맨 위에 “빠르게 시작하기” 카드
  • 단계 표시 ①–④와 작성 진행 표시
  • 문제 종류 바로 선택, 건물·층·호실 입력은 접어 둠
  • 공식 목록에 없는 건물·층·학과·학년·반·호실은 직접 입력
  • 사진 끌어놓기, 현재 탭 임시저장(글만 저장 · 사진과 AI 질문 답변은 저장 안 함)

작성 도우미

  • 학교급·장소에 맞춘 예시 89종, 문제 종류로 거르기
  • 예시를 고르면 제목·장소·분류·설명이 채워짐
  • 설명의 [ ] 빈칸이 남아 있으면 접수되지 않음
  • 고르기 전 내용으로 되돌리기
  • 학교마다 예시 24개 이상(테스트로 검사)

📷 사진 한 장으로 신고

사진을 찍거나 고르면 AI가 제목·장소·문제 종류·설명 초안을 채웁니다. 장소·종류는 학교 목록 값만 받고, 설명에 “언제부터”·“불편한 점” 빈칸을 넣어 학생이 확인해야 접수됩니다. 사람이 보이면 얼굴 자리를 모자이크하고, 가리기 도구로 더 가릴 수 있습니다. 분석 요청은 저장하지 않으며, AI 키가 없으면 기능이 숨겨집니다.

🔊 소음 재기

문제 종류가 “소음 문제”면 휴대폰 마이크로 10초 동안 소리 크기를 재서 평균·최고 dB를 붙입니다. 녹음하지 않고 숫자만 남기며, 기기마다 마이크가 달라 “추정치”로 표시합니다.

🖼️ 사진 첨부 규칙

신고당 6장, 장당 5MB까지 PNG·JPG·GIF·WEBP만 받습니다. 형식은 확장자가 아니라 파일 내용으로 확인합니다.

4. 분류 체계

위치 유형 (10)

교실복도화장실계단급식실체육관운동장도서관특별실기타

문제 종류 (7)

시설 고장안전 위험위생 문제환경 문제소음 문제불편 사항기타

세부 장소 상태

  • 공식 확인 — 학교 공식 현황 페이지에 나온 곳
  • 확인 필요 — 학교 게시판·뉴스 등 여러 곳에서 언급된 곳
  • 직접 입력 — 학생이 쓴 값. 공식 위치로 승격되지 않음

처리 상태 (6)

접수 대기→ 확인 중→ 담당자 배정→ 조치 예정→ 처리 중→ 처리 완료

처리 완료 뒤 신고자가 “아직 그대로예요”라고 답하거나, 공감 학생의 👎가 2명 이상이면서 👍보다 많으면 상태가 확인 중으로 돌아갑니다.

5. 내 신고 식별 · 다른 기기 연결

  • 신고를 등록하면 서버가 추측할 수 없는 소유 토큰을 발급합니다. 브라우저에는 원본, 서버에는 SHA-256 해시만 저장합니다.
  • 접수 화면에서 확인 코드(예: ABCDE-FGHJK)를 한 번 보여 줍니다. 서버에는 해시만 남습니다.
  • 휴대폰을 바꾸거나 브라우저 데이터를 지워도 “내 신고” 탭에서 접수번호 + 확인 코드를 넣으면 그 기기용 토큰을 새로 받습니다(신고마다 최근 10개 기기).
  • 어느 값이 틀렸는지 알려 주지 않고, 시도 횟수를 제한해 코드 대입을 막습니다.
  • 확인 코드 기능이 생기기 전에 접수한 신고는 불러올 수 없습니다.

6. 조회 · 통계 · 보고서

  • 내 신고 / 전체 신고 탭, 검색과 카테고리·위험도·처리 상태·기간 필터 조합
  • 필터 판정 규칙(reportFilter.ts)은 서버와 화면이 같은 코드를 씀
  • 위치별 신고 현황: 장소별 총 건수, 가장 많은 카테고리, 높음 이상 건수, 최근 신고 날짜. 서버가 실제 DB로 계산하고, 결과가 없으면 안내 문구 표시
  • AI 요약: 접수된 신고 전체의 문제 상황을 간결하게 정리 (Rate Limit + 캐시)
  • PDF 저장 / 인쇄: 현재 필터 목록을 보고서 형태로. 별도 라이브러리 없이 @media print + window.print()

7. 학생 참여 기능

🙋 나도 겪었어요

같은 문제를 겪은 학생은 새로 신고하는 대신 공감합니다. 기기마다 한 번만 세고, 운영진은 공감 많은 순으로 정렬합니다. 처리 완료된 신고에는 새로 공감할 수 없습니다.

✅ 만족도 확인

처리 완료된 내 신고에 “해결됐어요 / 아직 그대로예요”로 답합니다. 미해결이면 신고가 다시 “확인 중”이 됩니다.

🔁 진짜 고쳐졌나요?

처리 완료되면 공감했던 학생에게 알림이 가고, 👍 고쳐졌어요 / 👎 아직 그대로예요를 누릅니다. 👎 2명 이상이고 👍보다 많으면 자동으로 다시 엽니다. 다시 완료되면 처음부터 셉니다.

💬 추가 설명

접수 뒤에도 설명과 사진(최대 3장)을 덧붙입니다(신고당 10번). 신고자와 학교만 보며, 신고와 같은 안전성 검사를 거칩니다.

📨 학교의 답변

운영진·교사가 신고한 학생에게만 보이는 답변을 남깁니다. 공개 “처리 결과”(처리 메모)와는 별개입니다.

🔔 처리 소식 알림

알림을 켜면 상태 변경·학교 답변·보류 신고 공개 때 Web Push가 옵니다. 알림에는 접수번호와 바뀐 상태만 담습니다. iPhone·iPad는 홈 화면에 추가한 앱에서만 됩니다.

🏆 내가 바꾼 학교

이 기기에서 한 신고·공감·확인으로 고쳐진 곳을 학년도(3월 시작)별로 보여 주고 카드 이미지로 저장합니다. 서버에 묻지 않고 기기 기록으로 계산합니다.

🧠

AI 분석

위험도 채점, 추가 질문, 위치 묶기, 안전성 검사. AI는 서버에서만 호출합니다.

8. 위험도 분석

신고를 접수하면 서버가 AI에게 5개 요소를 각각 0~4점으로 채점하게 하고, 점수 계산과 등급 결정은 서버가 합니다. AI가 보낸 점수·등급은 신뢰하지 않고 다시 계산하므로, 같은 신고를 여러 번 분석해도 결과가 흔들리지 않습니다.

risk_score = (즉시성×30 + 사고가능성×30 + 피해정도×25 + 지속성×10 + 영향범위×5) / 4
             + 반복 신고 가산(0~5)          ※ 최대 100
요소가중치의미
즉시성30지금 당장 다칠 수 있는가
사고 가능성30사고로 이어질 확률
피해 정도25사고가 나면 얼마나 큰가
지속성10문제가 계속되고 있는가
영향 범위5몇 명이 영향을 받는가
점수등급처리 기한
75~100긴급1일
50~74높음3일
25~49중간7일
0~24낮음14일
  • 반복 신고 가산 — 유사 문제로 판단(1~3) + 지속성 2 이상 + 실제 DB에 이전 신고가 있을 때만 +2 / +3 / +5. 신고 수가 많다는 이유만으로는 올리지 않습니다.
  • 긴급 우선 — 전선 불꽃, 실제 화재, 구조물 낙하 임박 같은 즉각적 위험은 점수보다 우선해 긴급으로 올리되, “화재 대피 훈련” 같은 문맥은 구분합니다.
  • 사람 검토 표시 — 긴급 등급이거나 점수가 등급 경계(25·50·75) ±3점 안이면 판정이 불안정하다고 보고 사람 검토가 필요하다고 표시합니다.
  • 모델은 gpt-5.6-terra, 실패하면 gpt-5.6-luna로 폴백합니다. 계산 로직의 단일 출처는 riskAnalysis.ts입니다.

9. AI 추가 질문

“학교가 별로예요”처럼 어디서 무엇을 확인할지 알 수 없는 신고는 저장해도 처리할 수 없으므로, 접수 전에 한 번 확인합니다.

신고 작성→ AI 확인→ 충분 → 위험도 분석 → 저장
↳ 부족 → 질문 1개 → 답변 → 다시 확인 (최대 3회)
  • 질문은 항상 하나. 여러 개가 오면 서버가 첫 질문만 남깁니다.
  • 기준은 “완벽한가”가 아니라 “처리 가능한가”. 장소와 문제만 알면 날짜·시각·인원 없이도 접수됩니다.
  • 대화 상태는 서버 메모리 세션에 있고, 충분해지기 전에는 DB에 저장하지 않습니다.
  • AI가 없는 사실을 만들면 거릅니다. 상세 위치는 학생 문장에 실제로 있는 표현만, 학생이 쓰지 않은 숫자가 든 요약은 버립니다.

10. 위치 정규화와 집계

집계 때 학생이 적은 상세 위치를 함께 쓰고, 표기가 흔들려도 확실할 때만 같은 장소로 묶습니다.

입력결과
“본관 3층 화장실” · “본관3층 화장실” · “3층 화장실”본관 3층 화장실 (3건)
“본관 3층 화장실” · “별관 3층 화장실”건물이 달라 분리
“3층 화장실” · “3층 남자화장실”같은 곳인지 몰라 분리
  • 건물이 빠진 표기는 같은 층·장소의 건물 지정 그룹이 정확히 하나일 때만 흡수합니다.
  • 전부 문자열 규칙이라 AI를 호출하지 않고, 같은 데이터면 항상 같은 결과가 나옵니다(locationStats.ts).

11. 안전성 검사 · 프롬프트 방어

  • Moderation — 신고 글과 첨부 사진을 서버에서 검사합니다. 검토가 필요하면 공개 목록·상세·통계에서 숨기고 운영진 검토 대기열에 둡니다. 검사 장애 때 사진이 붙은 신고는 자동 공개하지 않고 보류합니다.
  • 욕설 필터 — 규칙 기반. 금지어 글자 사이 구분자를 허용하는 정규식으로 씨 발·씨.발 같은 우회를 잡되, 문장 전체 공백을 지우지 않아 “보지 못했어요” 같은 정상 문장을 오탐하지 않습니다.
  • Prompt Injection — 신고 내용은 <report> 안의 데이터로 고정하고, 그 안의 지시문은 실행하지 않습니다.
  • 사진 초안 검사 — AI 답의 장소·종류가 학교 목록에 있는 값인지 확인하고, 설명은 서버가 빈칸을 넣어 조립합니다(photoDraft.ts).

13. 역할과 권한

권한 순서는 총괄 > 관리자 > 운영진 > 교사입니다. 관리자가 “계정 관리” 화면에서 사람마다 개인 계정을 만들고, 처리 이력에는 바꾼 사람의 이름이 남습니다.

역할범위할 수 있는 일제한
총괄 (1명)전체관리자 계정 만들기·바꾸기, 백업으로 되돌리기, 총괄 자리 넘기기총괄 계정은 누구도(공용 비밀번호 관리자 포함) 바꾸거나 끄거나 지울 수 없음
관리자전체모든 기능 + 운영진·교사 계정 관리, 삭제된 신고 되살리기·영구 삭제, 운영 기록, 백업총괄이 없을 때만 관리자 계정도 관리하고 총괄을 지정
운영진모든 학교신고 처리·삭제, 공개 보류 검토, 학교 신청·등록, 알림 설정삭제·거절은 개인 계정으로만
교사소속 학교상태·담당자·처리 메모·학생 답변삭제, 검토 대기열, 학교 신청 메일함 불가
  • 공용 비밀번호도 계속 씁니다: STAFF_PASSWORD_HASH(아이디 admin 또는 비움, 관리자 권한), 학교별 SCHOOL_TEACHER_PASSWORD_HASHES. 처음에는 공용 비밀번호로 들어가 개인 관리자 계정을 만듭니다.
  • 세션은 HttpOnly·SameSite=Strict 쿠키, 8시간. 세션 해시를 저장소에 함께 저장해 서버가 잠들었다 깨거나 재배포돼도 유지됩니다.
  • 계정을 끄거나 비밀번호를 바꾸면 열려 있던 로그인이 바로 끝납니다. 켜진 관리자가 하나도 없게 되는 변경은 막습니다.

14. 운영진 화면

  • 목록 30초 자동 갱신. 처리 내용을 입력하는 중에는 건너뜁니다.
  • 새 신고·새 추가 설명에 “새로 들어옴”·“새 추가 설명” 표시, 브라우저 탭 제목에 건수
  • 상태·위험도별 요약, 검색·필터, 위험도 우선·공감순·기한 초과 정렬
  • 현재 조건의 신고 목록 CSV 내려받기
  • 처리 이력: 상태·담당자·학생 답변 변경, 안전성 검토, 삭제·되살림, 추가 설명, 만족도 응답을 누가(운영진/교사/신고자/시스템) 언제 했는지
  • 월별 통계: 접수·완료율·평균 처리 시간·기한 초과 완료, 유형·위치·위험도별 접수, 최근 6개월 추이. 한국 시간 월 경계, 인쇄·PDF·“디스코드로 보내기”
  • 학교 신청 메일함에서 “승인하고 학교 등록” → 재배포 없이 학교 선택 화면에 바로 표시

16. 삭제 · 되살리기 · 운영 기록

  • 신고 삭제(사유 필수)·장난 신고 처리·검토 대기 삭제는 개인 계정으로만. 처리 이력과 운영 기록에 남습니다.
  • 휴지통: 관리자는 삭제된 신고를 되살리거나, 개인정보 삭제 요청처럼 꼭 필요할 때 영구 삭제합니다.
  • 사진은 삭제 후 30일(DELETED_PHOTO_RETENTION_DAYS) 비공개 보관. 그 안에 되살리면 함께 돌아옵니다.
  • 운영 기록: 로그인, 계정 생성·변경·중지·삭제, 총괄 지정·넘기기, 신고 삭제·되살림·영구 삭제, 백업·되돌리기, 학교 등록, 알림 설정 변경. 최근 1,000건, 관리자 이상 열람. 학생 정보와 실패한 로그인은 넣지 않습니다.

17. 백업 · 복구

  • 매일 한 번(한국 날짜 기준, 잠들어 있었으면 깨어날 때) 저장소 전체를 비공개 보관소(schoolfix-backups)에 저장, 최근 30개 유지
  • 관리자: “지금 백업”, 내려받기(?photos=1이면 사진 포함)
  • 총괄: 백업 시점으로 되돌리기. 직전 상태는 자동으로 따로 백업
  • 계정·로그인·학생 알림 구독은 되돌리지 않습니다(백업에 비밀번호 해시 없음).
  • 총괄 비상 복구: 환경 변수 OWNER_RESET_PASSWORD_HASH(+ OWNER_RESET_USERNAME)를 넣고 재배포하면 시작할 때 한 번만 적용되고 운영 기록에 남습니다. 로그인해서 비밀번호를 바꾼 뒤 두 값을 지웁니다.

18. 반복 신고 · 공개 보류

학교는 학생 전체가 IP 하나를 쓰는 경우가 많아, 브라우저별 기기 토큰(서버에는 해시만)으로 구분합니다.

조건처리
10분 안에 3건 초과거부하지 않고 공개 전 운영진 검토
하루 10건 초과
“장난 신고로 처리”된 기기 (30일)
안전성 검사에 걸린 글·사진검토 대기열 보관, 승인 또는 거절(거절은 개인 계정)

검토 대상 기기 목록은 운영진 화면에서 보고 해제할 수 있습니다(abuseGuard.ts).

26. 보안

로그인이 없다는 것이 보안이 없다는 뜻은 아닙니다.

입력 검증

프론트엔드 검증을 믿지 않고 서버가 최종 판단. 허용된 위치·종류, 길이 제한, 사진은 내용으로 형식 확인.

Rate Limit

신고 등록·AI 요약·확인 코드·알림 구독·추가 설명에 각각 적용. 학교 NAT를 고려해 신고 한도는 여유 있게. 로그인은 틀린 비밀번호만 셈(15분 10번).

계정 · 세션

bcrypt 해시만 저장. 없는 아이디도 같은 시간이 걸려 존재 여부가 드러나지 않음. 쿠키는 HttpOnly·SameSite=Strict, 서버엔 SHA-256 해시만.

삭제 책임

신고를 지우는 모든 일은 개인 계정 + 사유. 공용 관리자 비밀번호 삭제 기능(ADMIN_PASSWORD_HASH)은 없앰.

저장 충돌 방지

마지막으로 읽은 버전(updated_at)이 그대로일 때만 씀. 충돌하면 최신 내용을 다시 읽어 같은 작업을 재적용. 다른 서버 변경은 30초마다 가져옴.

학생 알림

공식 푸시 서비스 주소(FCM·Mozilla·Apple·WNS)만 구독으로 받아 임의 주소 요청(SSRF)을 막음. 실제 신고의 소유 토큰에만 묶음.

XSS · 헤더

React 기본 escape, dangerouslySetInnerHTML 미사용. CSP, X-Frame-Options, Referrer-Policy, HSTS(운영).

오류 비노출 · 비밀 값

사용자에게는 일반 메시지만, 상세는 서버 로그. 평문 비밀번호·키는 코드·번들·DB·로그 어디에도 두지 않음.

27. 배포 · 운영

  • 배포: PR을 main에 병합하면 Render가 바로 배포 (render.yaml Blueprint). 비밀 값은 Render Environment에만.
  • CI: PR마다 GitHub Actions(ci.yml)가 타입 검사·빌드·단위 테스트·e2e를 돌림. 빨간 X면 병합하지 않음.
  • 확인: /api/health가 {"status":"ok"}, dataStore: "supabase", persistence.durable: true
  • 영구 저장: supabase/schema.sql 실행(업데이트마다 다시) → SUPABASE_URL + SUPABASE_SECRET_KEY. REQUIRE_SUPABASE_STORE=true면 설정이 빠진 배포는 시작하지 않음.
  • 사진·백업: 비공개 버킷 report-photos, schoolfix-backups (없으면 서버가 생성). 공개로 바꾸지 않음.
  • 무료 플랜 잠들기 대응: 한국 시간 7~21시(KEEP_AWAKE_HOURS)에 10분마다 자기 주소 호출 + Actions(wake-up.yml)가 06:50에 깨우고 낮에 14분마다 호출. 하루 14시간이면 한 달 약 440시간(계정 전체 750시간 한도).

30. 알려진 제한

  • 운영진 화면은 30초마다 다시 받아옴(WebSocket 아님). 바로 알아야 하면 웹훅 알림을 함께 사용
  • Rate Limit이 인메모리. 인스턴스를 늘리면 Redis 같은 공유 저장소 필요
  • 욕설 필터는 모음 삽입 우회를 잡지 못함(정상 문장 오탐 방지를 위해 의도적으로 제외)
  • AI 추가 질문 대화는 서버 메모리에 있어 재시작하면 처음부터
  • 확인 코드가 없는 예전 신고는 다른 기기에서 불러올 수 없음
  • 백업 되돌리기는 계정·로그인·알림 구독을 바꾸지 않음. 보관 기간이 지난 사진은 복구 불가
  • 학생 알림은 브라우저에 따라 다름(iOS는 홈 화면 앱, 일부 인앱 브라우저 불가)
